# План реалізації версії v1.0 (`stud_helper_bot`)

Послідовність розробки в ЛР №4 визначена на основі залежностей між предметними сутностями (`docs/design.md`) та зв'язків між варіантами використання (`«include»` та `«extend»`):

1. **Етап 1. Реалізація предметних сутностей та сховища даних:**
   - Створити класи предметної області `Student`, `Category`, `ReferenceInfo` та `Question`.
   - Налаштувати сховище даних та наповнити початкові категорії («Навчання», «Гуртожиток») і довідкові записи `ReferenceInfo` (розклад, правила, реквізити, контакти з ключовими словами `keywords`).
   - *Обґрунтування:* усі сценарії бота залежать від структури категорій та довідкових записів.

2. **Етап 2. Базова навігація по меню — UC-02 (базовий `«include»`-сценарій):**
   - Реалізувати реєстрацію/ідентифікацію користувача `Student` (`telegramId`, `username`, `registeredAt`).
   - Реалізувати вибір розділів меню `Student.selectCategory(categoryId)` («Навчання», «Гуртожиток») та навігацію «Назад».
   - *Обґрунтування:* на Use Case діаграмі навігація по меню включається (`«include»`) в усі основні користувацькі сценарії, тому реалізується першою.

3. **Етап 3. Отримання статичної інформації та реквізитів — UC-01:**
   - Реалізувати отримання елементів розділу `Category.getItems()` та форматування відповіді `ReferenceInfo.formatMessage()` (розклад дзвінків, правила, реквізити та інструкції для оплати).
   - Додати коректну обробку порожніх розділів.

4. **Етап 4. Пошук контактів за ключовим словом — UC-03:**
   - Реалізувати метод `Student.searchContact(keyword)` для пошуку контактів у `ReferenceInfo` за атрибутом `keywords`.
   - Реалізувати валідацію порожнього введення (A1) та повідомлення при відсутності збігів (A2).

5. **Етап 5. Відправка запитання адміністратору (розширення `«extend»`):**
   - Реалізувати створення звернення `Student.submitQuestion(text)` та пересилання його адміністратору (Куратору / Студраді) через `Question.forwardToAdmin()` як додаткову опцію у сценаріях.

6. **Етап 6. Інтеграція, перевірка критеріїв приймання та Sequence Diagram:**
   - Виконати перевірку всіх функціональних сценаріїв та заміряти час відповіді бота ($\le$ 2 с згідно з NFR-01).
   - Побудувати Mermaid Sequence Diagram у ЛР №4 на основі фактичної взаємодії компонентів у коді.
