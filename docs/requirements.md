# Специфікація вимог до програмного забезпечення (SRS) — `stud_helper_bot` (v1.0)

**Автор:** Антюшко Микита  
**Проєкт:** Telegram-бот для адаптації студентів-першокурсників КПІ ім. Ігоря Сікорського (`stud_helper_bot`)  
**Версія:** 1.0 (Baseline)

---

## 1. Загальний опис
`stud_helper_bot` — це інтерактивний Telegram-бот, призначений для швидкого надання студентам-першокурсникам актуальної довідкової інформації щодо навчального процесу, проживання в гуртожитку, реквізитів оплати та контактів адміністративних служб університету. Дані зберігаються у хмарному сховищі **Supabase**.

**Актори системи:**
- **Студент (Student)** — кінцевий користувач бота, який переглядає довідкову інформацію, користується меню та шукає контакти.
- **Адміністратор (Admin)** — відповідальна особа, яка підтримує актуальність довідкових записів у базі даних та обробляє запитання студентів.

## 2. Функціональні вимоги (Functional Requirements)

| ID | Назва вимоги | Опис вимоги | Пріоритет | Пов'язані UC |
| :--- | :--- | :--- | :--- | :--- |
| **FR-01** | Інтерактивна навігація по базовому меню | Система повинна надавати головне інтерактивне меню після команди `/start` із базовими категоріями («Навчання», «Гуртожиток», «Пошук контактів», «Задати питання»), підтримувати перехід до підрозділів та повернення назад кнопкою «Назад до меню». | Високий (Must) | UC-01, UC-02 |
| **FR-02** | Отримання статичної довідкової інформації | Система повинна завантажувати зі сховища (`Supabase`) та відображати структуровану довідкову інформацію (`ReferenceInfo`: розклад дзвінків, правила навчання/проживання, реквізити оплати) із зазначенням дати останнього оновлення (`updatedAt`) та inline-кнопкою з посиланням на офіційне джерело (`sourceUrl`). | Високий (Must) | UC-01, UC-02 |
| **FR-03** | Пошук контактів за ключовим словом | Система повинна приймати від студента текстовий запит (ключове слово), виконувати пошук серед записів `ReferenceInfo` за полем `keywords` та повертати перелік релевантних контактів (деканат, адміністрація гуртожитку, служби університету). | Високий (Must) | UC-03 |
| **FR-04** | Обробка некоректних дій та помилок | У разі введення нерозпізнаного тексту, порожнього пошукового запиту або відсутності збігів система повинна виводити зрозуміле повідомлення та пропонувати повторити дію або повернутися до головного меню. | Середній (Should) | UC-02, UC-03 |
| **FR-05** | Зворотний зв'язок («Задати питання») | Система повинна надавати студенту можливість звернутися до адміністратора у випадку, якщо потрібна інформація відсутня або розділ тимчасово недоступний. | Середній (Should) | UC-01, UC-02 |
| **FR-06** | Оновлення довідкових даних адміністратором | Адміністратор повинен мати можливість додавати, редагувати та видаляти категорії (`Category`) і довідкові записи (`ReferenceInfo`) у сховищі даних із фіксацією дати оновлення (`updatedAt`). | Середній (Should) | — |

| :--- | :--- | :--- | :--- | :--- |
| **NFR-01** | Продуктивність (Performance) | Час відгуку бота на натискання кнопок меню, запит довідкової інформації або пошук контактів має бути мінімальним для комфортної взаємодії. | Час відповіді ≤ 2 секунд за нормального інтернет-з'єднання. | UC-01, UC-02, UC-03 |

| **NFR-03** | Доступність (Availability) | Бот повинен працювати цілодобово для забезпечення доступу студентів до інформації в будь-який час. | Uptime ≥ 99% на місяць. | UC-01, UC-02, UC-03 |
| **NFR-04** | Безпека (Security) | Токен Telegram Bot API та ключі доступу до `Supabase` не повинні зберігатися у відкритому вигляді в репозиторії коду; права на редагування даних мають бути лише в адміністратора. | Використання змінних середовища (`.env`), розмежування ролей доступу. | — |

## 4. Критерії приймання (Acceptance Criteria)

| ID | Пов'язана вимога | Умова перевірки (Given / When / Then) |
| :--- | :--- | :--- |
| **AC-01** | FR-01, NFR-02 | **Given** студент відкрив чат із ботом. **When** він надсилає `/start` та натискає «Навчання» або «Гуртожиток». **Then** бот за ≤ 2 с відображає список підрозділів обраної категорії та кнопку «Назад до меню», натискання якої повертає головне меню. |
| **AC-02** | FR-02, NFR-01 | **Given** студент перебуває у підрозділі категорії «Навчання» або «Гуртожиток». **When** він обирає конкретну тему (наприклад, розклад або реквізити). **Then** бот надсилає структурований текст, дату останнього оновлення (`updatedAt`) та робочу inline-кнопку переходу на офіційний сайт (`sourceUrl`). |
| **AC-03** | FR-03, NFR-01 | **Given** студент обрав «Пошук контактів». **When** він вводить існуюче ключове слово (наприклад, «деканат»). **Then** бот за ≤ 2 с повертає список відповідних контактів із бази даних. |
| **AC-04** | FR-04, NFR-02 | **Given** студент вводить порожній рядок або неіснуюче ключове слово у пошуку, або надсилає довільний текст у головному меню. **Then** бот не завершує роботу з помилкою, а надсилає зрозумілу підказку й пропонує повторити дію або повернутися в меню. |
| **AC-05** | FR-05, NFR-02 | **Given** у базі даних відсутній запис або тимчасово втрачено з'єднання з `Supabase`. **When** студент намагається відкрити розділ. **Then** бот інформує про тимчасову недоступність даних і пропонує скористатися опцією «Задати питання». |
